# 后端接入后的前端样式恢复审查

日期：2026-09-14。

## 基准与边界

以 `a4f36da`（用户已确认的杭电蓝主题）为 UI 基准，审查至 `f937474` 的全部 `apps/web` 变更。阶段 1 的数据库持久化没有修改前端；主要视觉偏移发生在阶段 2–5 的模板和新增局部 CSS 中。`style.css` 与该基准完全一致，因此没有覆盖主样式或回退整个前端文件。

只恢复显示结构，保留真实账号、数据库、API、鉴权、状态流转、匹配配额、个人说明快照和联系权限。没有恢复写死的示例人数/申请记录，也没有把规则匹配或未接入的钉钉服务描述成已经上线。

## 验证

- `apps/web/tests/ui-regression.test.mjs`：26 项通过。其中 16 个原有组件的标签层级/静态类名与基准相同，主样式摘要相同；覆盖两类申请四种状态、长说明与快照标签映射。
- 结构测试不代表所有动态条件或像素均相同；已额外通过本地浏览器检查 390×844 手机布局和 320px 窄屏申请卡片，无横向溢出，底栏保持单行。
- 浏览器检查：两类发出/收到申请、详情到修改入口、个人首页、账号登录弹窗、匹配开始页、发布编辑弹窗；临时草稿通过真实 API 保存成功并返回列表，数据库确认投入、地点和标签未丢失。
- Vue TypeScript 检查、Vite 生产构建通过；原有后端 5 组、41 项测试通过。
- 仅用于视觉测试的 4 条申请、3 条机会（含草稿）、2 个临时账号已按精确 ID 清理，已有业务记录未回退。
- GitHub Pages 工作流增加前端结构回归测试，后续修改原布局时必须显式核对设计基准。

执行前端检查：`pnpm --filter @campus/web test`。这些测试不访问数据库、不消耗匹配次数。

## 登录入口后续修正

根据用户反馈，将原身份卡右侧箭头明确显示为“登录/账号”，保留原卡片结构；匹配未登录状态提供“去登录”，直接打开账号弹窗，登录完成后留在匹配页。账号入口每次打开重新获取开发账号，避免首次服务未启动后始终没有登录选项。开发服务连接错误与生产环境尚未开放登录分别提示。

机会列表移除额外的未排版“重新加载”和重复空状态；连接失败时统一在空状态中提供图标重试。新增两项前端回归检查，总计 28 项。
